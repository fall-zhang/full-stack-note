容器的存储有一个关键问题：**容器删除后，数据就没了**。

### 挂载方式

- 数据卷，创建数据卷，挂载到对应位置
- 主机目录（bind mount），目录映射
- tmpfs 挂载，数据放在内存中，快速读写但不需要持久化的数据

### 备份 volumn 数据

```sh
docker run --rm \
    -v my-vol:/source:ro \
    -v $(pwd):/backup \
    alpine tar czf /backup/my-vol-backup.tar.gz -C /source .

```

- 创建临时容器
- 挂载要备份的数据卷到 `/source`
- 挂载当前目录到 `/backup`
- 使用 tar 打包

### 恢复 volume 数据

```bash
## 创建新数据卷

docker volume create my-vol-restored

## 解压备份到新数据卷

docker run --rm \
    -v my-vol-restored:/target \
    -v $(pwd):/backup:ro \
    alpine tar xzf /backup/my-vol-backup.tar.gz -C /target
```

### Bind Mount



> **注意**：挂载单个文件时，如果宿主机上的文件被编辑器替换（而非原地修改），容器内仍是旧文件的 inode。建议重启容器或挂载目录。



### 生产实践

一般使用 volume 因为


| 维度      | bind mount         | Volume               |
| ------- | ------------------ | -------------------- |
| 路径管理    | 宿主机绝对路径            | Docker 命名管理          |
| 可移植性    | 差                  | 好                    |
| 生命周期    | 手动维护               | Docker 管理            |
| 初始化     | 直接覆盖，不复制           | 可复制镜像目录内容            |
| 安全隔离    | 易暴露宿主机             | 隔离更好                 |
| 驱动/远端存储 | 有限                 | 插件丰富                 |
| 备份迁移    | 手动找路径              | 标准工具/插件              |
| 编排集成    | 弱，类似 hostPath      | Compose/Swarm/K8s 集成 |
| 性能      | Linux 相近，Desktop 差 | Linux 相近，Desktop 好   |
